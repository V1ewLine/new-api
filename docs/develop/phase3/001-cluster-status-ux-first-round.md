# 集群状态易用性优化（第三阶段第一轮）

## 1. 开发目标

第三阶段第一轮聚焦管理员日常查看和排障路径，不改变遥测采集协议，也不调整历史数据存储方式。本轮解决以下问题：

- 页面只显示最近一次采集时间，无法判断当前指标是否仍然新鲜；
- 告警只显示错误码，缺少原因说明和直接操作；
- 一级、二级页面缺少明确的手动刷新入口；
- 刷新页面后，筛选、分页、详情标签页和图表时间窗口会丢失；
- 从模型集群页新增集群时，需要再次选择当前模型；
- 搜索输入处于防抖等待期时，导出条件可能与屏幕上的数据条件不一致。

## 2. 数据新鲜度

集群数据新增三种前端展示状态：

- `Fresh`：最近一次成功采样仍在允许窗口内；
- `Stale`：最近一次成功采样已经超过允许窗口；
- `No successful sample`：尚无成功采样。

过期窗口取以下两者中的较大值：

```text
3 × 集群状态自动刷新间隔
30 秒
```

这样可以容忍短暂网络抖动，也避免刷新间隔较短时频繁把数据标为过期。

展示位置：

- 模型集群列表：同时显示最近成功时间和最近尝试时间；
- 集群详情概览：主指标改为“最近成功采样”，并保留最近尝试时间；
- 集群详情趋势区域：显示数据新鲜度；
- 活跃告警：显示最近成功、最近尝试和连续失败次数；
- 集群详情：存在旧遥测数据但已经过期时，显示明确提示，说明页面当前数值来自哪次成功采样。

## 3. 可操作告警

常见采集错误不再只展示原始错误码，而是映射为可读原因和建议：

- `AGENT_TIMEOUT`：提示 Agent 负载或网络延迟，并允许立即重试；
- `AGENT_UNREACHABLE`：提示检查地址、端口、防火墙和服务状态，并允许立即重试；
- `AGENT_HTTP_401` / `AGENT_HTTP_403`：提示重新生成并部署 Agent Token；
- `AGENT_ADDRESS_BLOCKED`：提示检查出站请求策略和 Agent 地址白名单；
- `AGENT_SCHEMA_*`：提示 Agent 与 New API 的版本或数据格式不兼容；
- 集群密钥不可用：提示重新生成 Agent Token；
- 未识别错误：保留原始错误码，并允许立即重试。

一级页面的告警卡片提供：

- 查看集群详情；
- 对可重试错误执行“立即重试”；
- 重试期间的禁用和加载反馈。

三级页面继续保留原始错误码用于排查，同时使用同一套友好说明。“刷新”操作改名为“立即采集”，明确该操作会请求 Agent，而不仅是重新渲染页面。

## 4. 刷新与失败恢复

- 一级页面工具栏新增手动刷新按钮，同时刷新当前概览和模型筛选选项；
- 二级模型页面新增手动刷新按钮；
- 一级、二级、三级查询失败状态均提供重试按钮和加载反馈；
- 自动刷新继续使用“系统设置 → 控制台内容 → 数据仪表盘”的集群状态刷新间隔；
- 二级页面显示当前自动刷新间隔，手动刷新按钮继续保留。

## 5. URL 状态保留

一级页面把以下状态写入 URL 查询参数：

| 查询参数 | 说明 |
| --- | --- |
| `q` | 集群或模型搜索词 |
| `model` | 模型筛选 |
| `status` | 健康状态筛选 |
| `page` | 当前页 |
| `pageSize` | 每页数量 |

三级页面把以下状态写入 URL 查询参数：

| 查询参数 | 说明 |
| --- | --- |
| `tab` | `overview`、`engine` 或 `machine` |
| `range` | `15m`、`1h`、`6h`、`24h`、`7d` 或 `custom` |
| `start` | 自定义时间窗口开始时间，ISO 8601 |
| `end` | 自定义时间窗口结束时间，ISO 8601 |

路由使用 Zod 校验查询参数。无效或缺失的时间范围安全回退到最近一小时。刷新页面、复制链接或使用浏览器前进后退时，页面状态可以恢复。

## 6. 新增集群和导出

- 模型集群页面新增“添加集群”入口；
- 从该页面打开新增弹窗时，自动预选当前模型；
- 模型无集群的空状态也提供新增按钮；
- 一级页面无匹配集群时提供新增按钮；
- 一级页面导出使用与当前数据请求相同的防抖搜索条件，保证下载内容与屏幕结果一致。

## 7. 后端接口变化

`GET /api/clusters/overview` 的告警对象新增：

```json
{
  "last_success_at": 0,
  "consecutive_failures": 0
}
```

两个字段来自现有 `clusters` 表，用于前端判断新鲜度和展示连续失败次数。现有字段保持不变。

本轮没有新增数据库表、字段或索引，不需要迁移。PostgreSQL、MySQL 和 SQLite 部署均直接使用现有数据；Redis 不参与本轮状态持久化。

## 8. 国际化

新增的新鲜度、刷新、告警说明和重试文案均接入 i18next。翻译通过 `web/scripts/add-missing-keys.mjs` 写入，并同步以下语言：

- English
- 简体中文
- 繁体中文
- Français
- 日本語
- Русский
- Tiếng Việt

## 9. 自动化验证

后端：

```bash
GOCACHE=/tmp/new-api-go-cache go test ./service/clusterstatus
```

覆盖概览告警返回最近成功时间和连续失败次数。

前端：

```bash
cd web
./node_modules/.bin/tsgo -b
./node_modules/.bin/oxlint -c .oxlintrc.json \
  src/features/cluster-status \
  src/routes/_authenticated/cluster-status
node --experimental-strip-types --test \
  src/features/cluster-status/__tests__/*.test.ts
node scripts/find-missing-keys.mjs
node scripts/sync-i18n.mjs
node scripts/add-copyright.mjs --check
./node_modules/.bin/rsbuild build
```

本轮新增测试覆盖：

- 尚无成功采样、新鲜和过期三种判断；
- 最小 30 秒和三次刷新容错窗口；
- 临时故障允许重试，凭据和格式错误引导配置；
- 自定义图表时间范围在 URL 中保留到秒；
- 无效自定义范围安全回退；
- 从模型页面新增集群时预选当前模型。

以上测试、类型检查、Lint、国际化校验和生产构建均通过。
