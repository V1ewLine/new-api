# 当前集群负载聚合与趋势（第三阶段第二轮）

## 1. 开发目标

本轮统一一级“集群状态”和二级“模型集群”页面中的请求数、Token 数语义，移除容易被误解为累计值的展示方式，并增加与三级页面一致的历史趋势能力。

- 一级页面展示所有模型、所有监控中集群的当前负载；
- 二级页面只展示当前模型下所有监控中集群的当前负载；
- 三级页面及其原有指标口径保持不变；
- 一级列表筛选不再改变全局汇总卡片和趋势图；
- 当前请求数和当前 Token 占用分别显示上报覆盖率；
- 两个页面都提供共享时间窗口、自动刷新、手动刷新和图表放大能力。

## 2. 指标定义

### 2.1 当前请求数

单个集群的当前请求数定义为：

```text
engine.running_requests + engine.waiting_requests
```

只有两个字段都存在且为非负有限数值时，当前请求数才视为可用。一级页面将所有有效集群的结果相加；二级页面只汇总当前模型的有效集群。

### 2.2 当前 Token 占用

单个集群的当前 Token 占用直接使用：

```text
engine.token_usage
```

字段存在且为非负有限数值时才参与聚合。该指标表示 Agent 当前上报的 Token 使用量，不代表历史累计消耗。

### 2.3 有效监控集群与新鲜度

汇总分母“监控中集群”满足：

- 集群已启用；
- Agent 凭据状态为 `active`。

当前卡片的分子还必须满足：

- 已有成功遥测；
- 最近成功时间未过期；
- 对应指标字段完整有效。

过期窗口与第三阶段第一轮保持一致：

```text
max(3 × 集群状态刷新间隔, 30 秒)
```

暂停、待验证、已删除、无成功采样或数据过期的集群不贡献当前值。某一指标没有任何有效上报时，前端显示 `—`，不会显示有误导性的 `0`。

兼容旧客户端的 `total_requests`、`total_tokens` 字段暂时保留，但返回值与新的当前负载字段一致。新前端只读取语义明确的字段。

## 3. 汇总范围与筛选

一级页面的全局汇总、全局趋势和告警使用未筛选的全部集群。搜索、模型、状态和分页参数只作用于下方模型列表，并在界面中明确提示。

二级页面根据 URL 中的模型 ID 确定范围，汇总卡片、趋势和集群列表都只包含该模型的集群。

接口新增覆盖率字段：

- `monitored_clusters`
- `requests_reporting_clusters`
- `tokens_reporting_clusters`
- `current_requests_available`
- `current_token_usage_available`

## 4. 聚合趋势接口

新增两个管理员接口：

```text
GET /api/clusters/telemetry/trends
GET /api/clusters/models/:modelId/telemetry/trends
```

查询参数沿用三级页面：

- `start_at`：RFC3339 开始时间，包含；
- `end_at`：RFC3339 结束时间，不包含；
- `max_points`：最大图表点数。

后端根据时间跨度选择跨数据库兼容的时间桶。每个时间桶内，先为每个集群选择最后一条成功采样，再计算当前请求数和当前 Token 占用的合计，避免同一集群在一个桶内被重复累加。

每个趋势点同时返回请求数覆盖率和 Token 覆盖率。没有有效采样的时间桶仍返回空值点，前端以曲线断点显示，不插值、不补零。历史查询范围受“集群遥测数据保存天数”限制。

数据库聚合使用 GORM 与 SQLite、MySQL、PostgreSQL 均支持的分组表达式；集群 ID 和历史记录 ID 分批查询，避免大规模集群场景下超过数据库参数数量限制。

## 5. 前端交互与布局

一级页面顺序调整为：

1. 页面操作：导出、手动刷新、新增集群；
2. 全局汇总卡片；
3. 全局当前负载趋势；
4. 搜索、模型和状态筛选；
5. 模型列表与全局告警。

二级页面顺序调整为：

1. 页面操作；
2. 当前模型汇总卡片；
3. 当前模型负载趋势；
4. 集群列表。

两个趋势图在桌面端一行两列，在小屏幕上自动堆叠：

- 当前请求数趋势；
- 当前 Token 占用趋势。

页面级时间窗口同时应用于两张图，支持最近 15 分钟、1 小时、6 小时、24 小时、7 天和精确到秒的自定义范围。相对时间窗口按系统配置的刷新间隔自动更新，自定义固定窗口不自动移动。

每张图右下角保留展开按钮。展开后的浮层拥有独立时间窗口，不会修改页面级时间窗口。图表提示框和卡片底部同时显示上报集群数与监控中集群数，便于识别部分数据缺失。

一级和二级页面的时间窗口写入 URL，刷新或复制链接后可以恢复。

## 6. 验证

本轮覆盖以下回归检查：

- 全局当前值不受搜索、模型、状态和分页筛选影响；
- 当前值使用引擎字段，不读取可能为累计语义的旧聚合字段；
- 过期、暂停和待验证集群不贡献当前值；
- 二级页面不会混入其他模型的数据；
- 多集群历史采样按时间桶正确聚合；
- 无采样时间桶保留为空值断点；
- 新增趋势路由继续受管理员认证保护；
- Go 服务测试、前端 TypeScript 检查、Oxlint、i18n 完整性检查和生产构建通过。
