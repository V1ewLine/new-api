# 模型调用分析 CSV 导出开发记录

## 1. 开发目标

在“数据看板 → 模型调用分析”页面增加独立的数据导出能力，允许用户按模型、时间范围和时间粒度下载可直接用于数据分析的 CSV 文件。

本次实现遵循以下交互约定：

- 导出入口位于模型调用分析页面右上角，与图表设置、筛选按钮并列。
- 导出弹窗沿用“模型分析筛选”的时间选择样式。
- 弹窗默认继承当前页面已应用的时间范围、时间粒度和管理员用户名筛选，但在弹窗内修改导出条件不会改变页面筛选。
- 模型下拉框支持搜索，默认选择“所有模型”。
- 普通用户只能导出自己的数据；管理员可以导出全站数据或指定用户名的数据。

## 2. 前端实现

### 2.1 导出弹窗

新增文件：

- `web/src/features/dashboard/components/models/models-export-dialog.tsx`

弹窗包含：

- 模型选择：所有模型或指定单个模型。
- 快速范围：1 天、7 天、14 天、29 天。
- 自定义开始时间和结束时间。
- 时间粒度：小时、天、周。
- 管理员用户名筛选。
- 浏览器时区、实际导出范围和数据量限制提示。
- 导出中的加载状态、成功提示和失败提示。

可导出模型列表会根据当前时间范围和管理员用户名动态请求。修改时间范围、粒度或用户名后，模型列表使用新的条件重新加载，避免选择当前范围内没有数据的模型。

### 2.2 时间范围处理

新增文件：

- `web/src/features/dashboard/lib/model-export.ts`

导出使用完整的自然时间段：

- 小时：向下对齐到整点。
- 天：向下对齐到当天 00:00:00。
- 周：向下对齐到周一 00:00:00。
- 结束时间使用排他边界；如果用户选择的结束时间不在边界上，则向后扩展到下一个完整时间段。

前端与后端使用相同的对齐规则。弹窗会显式展示实际生效的导出范围和浏览器 IANA 时区。

### 2.3 下载处理

新增的前端接口：

- `getModelAnalyticsExportModels`
- `downloadModelAnalyticsExport`

下载响应必须包含 `Content-Disposition`。如果后端返回业务错误 JSON，前端会读取错误消息并显示失败反馈，不会将错误 JSON 当作 CSV 下载。

文件名支持标准 `filename` 和 UTF-8 `filename*` 解析，并提供固定的兜底文件名。

## 3. 后端实现

### 3.1 路由与权限

新增接口：

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/data/models` | 管理员 | 查询指定条件下可导出的模型 |
| GET | `/api/data/self/models` | 登录用户 | 查询当前用户可导出的模型 |
| GET | `/api/data/export` | 管理员 | 导出模型调用分析 CSV |
| GET | `/api/data/self/export` | 登录用户 | 导出当前用户的模型调用分析 CSV |

普通用户接口从认证上下文读取用户 ID，不接受客户端传入用户 ID 或用户名来改变数据范围。管理员接口允许使用可选的 `username` 参数。

### 3.2 请求参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `start_timestamp` | 是 | Unix 秒级开始时间 |
| `end_timestamp` | 是 | Unix 秒级结束时间，必须晚于开始时间 |
| `granularity` | 是 | `hour`、`day` 或 `week` |
| `timezone` | 是 | IANA 时区，例如 `Asia/Shanghai` |
| `model_name` | 否 | 不传表示导出所有模型 |
| `username` | 否 | 仅管理员接口生效 |
| `format` | 否 | 当前仅支持 `csv` |

### 3.3 聚合逻辑

数据来源为 `quota_data`，该表的数据最小精度为小时。后端先在数据库中按模型和小时汇总，再根据请求时区聚合成自然小时、自然日或自然周。

选择所有模型时不会合并成一条总计记录，而是每个“时间段 + 模型”输出一行，方便后续透视、分组和绘图。

CSV 字段：

| 字段 | 说明 |
| --- | --- |
| `bucket_start` | 时间段开始时间，RFC 3339 |
| `bucket_end` | 时间段结束时间，RFC 3339 排他边界 |
| `timezone` | 导出使用的 IANA 时区 |
| `granularity` | 时间粒度 |
| `model_name` | 模型名称 |
| `request_count` | 时间段内请求数 |
| `token_used` | 时间段内 Token 使用量 |
| `quota` | 时间段内额度消耗 |
| `rpm` | 请求数除以该时间段的实际分钟数 |
| `tpm` | Token 数除以该时间段的实际分钟数 |

CSV 使用 UTF-8 BOM，便于常见表格软件正确识别中文。模型名称和时区字段会防护以 `= + - @` 开头的表格公式注入内容。

### 3.4 范围与资源限制

- 小时粒度：最多 90 天。
- 天粒度：最多 2 年。
- 周粒度：最多 5 年。
- 单次导出最多 200,000 行。
- 可选模型列表最多 10,000 项。
- 没有匹配数据时返回明确的业务错误，不生成空文件。

查询与聚合使用 GORM 和通用 SQL 聚合语法，可同时支持 SQLite、MySQL 和 PostgreSQL。

### 3.5 审计

管理员执行导出后会记录管理审计日志，包含：

- 模型范围。
- 时间粒度。
- 实际开始和结束时间。
- 导出行数。
- 模型数量。

审计日志不记录 CSV 内容。
